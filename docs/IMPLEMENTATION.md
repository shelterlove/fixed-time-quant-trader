# v2 实现与清理说明

生产代码被压缩为六个职责明确的模块：配置、策略、交易所、状态、引擎和只读面板。研究回放没有进入部署镜像；历史 Markdown 按原目录保存在 `research-history/`。

## 复用边界

复用的是 Binance REST 端点、精度处理、SQLite WAL 和 Docker Compose 骨架。信号数学来自已经核验的 v2 独立重建。旧的三单位组合、P90/P9.1、回撤加杠杆、仓位驱逐、旧 08 空头、shadow seed 和旧研究 CLI 均未复用。

## 状态与升级

新账本以 lot 为中心。普通订单与条件单在发送前保存 client ID，结果不确定时先查询。普通成交的累计数量、已入账数量与 lot 更新在同一 SQLite 事务内提交，重复回报只应用增量。批次预算在提交首单前冻结，重试不重新分配。

首次旧版升级要求旧仓位先正常结束，避免只迁移数量却遗漏旧订单状态。旧表保留作审计输入，已有 v2 账本沿用。行情采集在单独线程进行，退出、对账和权益采样留在主线程；SQLite 只有主线程写入。

## 测试网故障修复

- `-1021`：签名时间使用测试网服务器校时并向后偏置 250ms；遇到该明确拒绝码时重新校时并安全重试一次，`recvWindow=5000`。
- `-1100`：client order ID 只包含 `ft2-`、角色和 SHA-256 十六进制摘要，币名或本地化字符不会进入参数。
- `-2022`：Hedge Mode 平仓不发送 `reduceOnly`；先核对方向总量，再取消该 lot 条件单、核对其成交，最后发主动平仓。拒绝后重新读取仓位，保留缺失成交待核对。
- `cannot value equity...`：权益直接取交易所 wallet balance 加未实现盈亏，不再依赖本地数量先完全解决；数量不一致仍会阻止新开仓。
- `position disappeared without sufficient exit fills`：先查询条件单及对应实际订单。仍缺成交时保留本地记录并暂停新增仓位；权益独立更新。成交回报恢复后自动入账、解除对应事件。若交易所始终不提供记录，需人工核对，不能伪造平仓收益。

## 本次审查结论与边界

修复了非原子成交入账、部分成交重复扣量、条件单提交中断恢复、重试预算漂移、跨日止损锁、单个仓位异常阻断其他仓位、健康检查不检查心跳等问题。`live-check` 已改为只读，不初始化数据库或记录部署。

尚有明确执行边界：+30% 延长激活与 +300% 保护激活仍按轮询价格判断，可能漏过两次采样间或停机期间的短暂触及；硬止损和 +400% 使用交易所条件市价单，触发价不等于保证成交价。信号参考价来自正式市场已收盘小时线，测试网成交价可能偏离，30% 是相对该参考价的规则，不等同于实际成交价的精确亏损比例。离线 OHLC 回放不等同于实时逐笔执行。

账户权益包含交易所实际费用与资金费；当前简化账本没有完整的逐笔手续费、资金费归因报表。旧实验代码已清理；现在以 `research/` 最小流水线重新建立共享策略实现的连续账户基线，见[正式基线](../reports/baseline_20260919/REPORT.md)及[数据复核说明](../reports/baseline_20260919/REVIEW.md)。

接口契约核对依据：[Binance USD-M Trade API](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade)。
