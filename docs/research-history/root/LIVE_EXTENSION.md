# 测试网 24h 多头延长规则

本规则同时作用于标准历史回放和 Binance USDⓈ-M Futures 测试网执行层。唯一策略参数位于 [`strategy.toml`](strategy.toml) 的 `long.extension`；[`testnet.toml`](testnet.toml) 必须与它保持一致，当前固定为 `4h / 24h / 4h`。

## 触发与退出

`v1.5.0` 新仓使用 `exchange-5s-v2`：从实际成交时间之后读取测试网新增成交，累计最高价，记录程序首次观察到 `+30%` 的时刻。重启补到的旧成交不会被倒填为过去的激活时刻。

到原计划退出时刻 `E`，只有同时满足下列条件，持仓才延长：

1. 尚未被 P90 保护退出；
2. 首次保护激活时刻位于 `(E - 4h, E]`；
3. 未被交易所托管的硬止损关闭。

符合条件时，计划时间退出改为 `E + 24h`。延长期间：

- 继续更新交易所托管的 P90 保护单，保护价只收紧；
- 原交易所硬止损持续有效；
- 到 `E + 24h` 仍未退出时，以市价单退出，原因为 `EXTENSION_CAP`。

延长持仓的退出不会写入 P90 训练历史；P90 仍只由基础影子候选更新。

标准回放先用基础持仓路径确定 P90 与激活时刻，只为符合延长条件的交易加载计划退出后的额外分钟和资金费数据。延长交易进入同一个三单位组合回放，并使用与测试网一致的“空头优先、已释放延长多头其次”挤出顺序。

## 容量顺序

若新多头需要容量，程序依次：

1. 按优先级从差到好关闭空头；
2. 仍不足时，只关闭已经超过 `E + 4h` 释放时刻的延长多头，按最早释放时刻优先。

普通多头，以及尚未超过 `E + 4h` 的延长多头，不会被这一规则让位关闭。

## 升级行为

SQLite 保存计划退出、首次保护激活、延长状态、释放时刻和最终上限。已有持仓标记为 `minute-v1`，保留原分钟逻辑和已冻结的 P90；只有新仓使用交易所增量保护。旧仓首次激活时间未知时不延长。交易所已挂保护在进程离线期间仍可触发，继续抬高保护价和时间退出需要程序在线。

旧分钟研究无法精确重现 5 秒内价格顺序、撤挂延迟和实际成交。历史 24h 延长收益仍是分钟模型结果，新执行版本应依据测试网实际成交记录单独评价。

部署、升级和监控命令见 [`OPERATIONS.md`](OPERATIONS.md)。
