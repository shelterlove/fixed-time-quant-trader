# v1.7.0 修复与验收

日期：2026-09-07。信号参数、当前三单位容量、回撤倍率、硬止损和 P90 参数保持不变。用户确认 9 月 5 日的三笔测试网交易采用五仓配置，历史仓位结构正常；本次不按三仓规则重写旧交易。

## 修改

### 多头让位

先冻结候选、单位、让位名单、净值与 P90 样本，再预检标的和资金。让位预检将待平仓的逐仓钱包及未实现盈亏计入预计可释放资金，并扣除 0.3% 名义金额缓冲；只评估计划中尚未平掉的仓位。字段不足或数量不一致时跳过，不据不完整信息平仓。字段依据见 [Binance Position Information V2](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/Position-Information-V2)。释放金额是代码估计，成交后余额才是最终依据。

确认让位平仓后，重新读取余额、过滤器与价格，在原批次净值基础上计算数量。资金仍不足或决策超期，保存 `SKIPPED_AFTER_EVICTION`；失败决策保留已计划的让位明细。超过期限不再发起其余让位退出。未完成的退出意图仍按原恢复机制继续解决，不重复开新仓。

### 回测账本

逐笔执行结果新增 `entry_fill`、`entry_cost_return`。多头使用含入场滑点的成交价计量数量和浮动盈亏；入场手续费在入场时记账。空头保留原 0.3% 往返压力成本模型，平均分配到入场、退出两侧，仍不引入原规格排除的空头资金费。

多头资金费在其发生后的首个完整分钟记账，整分钟事件直接在该时刻记账；同一时刻先结算原持仓资金费、到期退出，再冻结新仓资金。每个持仓只遍历自己持有区间的资金费，避免每分钟扫描全部历史。平仓用逐笔净收益减去已经记账的现金流结算，防止重复扣款。

持仓成本发生时间会影响回撤档位和后续名义金额，因此修复后的净值可以高于或低于旧算法。验收要求现金流和逐笔盈亏闭合，不要求机械复现旧曲线。

### 研究窗口边界

产品流水线把 Window 传给延长数据需求和执行函数。延长期限取原计划 +24h 与窗口/研究子窗口终点的较早者。到达边界仍持仓时，按最后完整分钟收盘结算，原因 `WINDOW_END`；边界前实际触发止损或保护则保留实际退出原因。

延长不请求边界之后的分钟日期分区。归档文件按日/月提供，同一文件可能包含边界之后的数据，流水线在延长消费前按窗口过滤；每条路径另按对应子窗口边界截断。资金费保留 entry-exclusive / exit-inclusive 约定，恰在截断边界的结算事件用最后完整分钟收盘作为价格代理，避免读取下一窗口开盘。资金费月份需求覆盖边界事件。

输出 manifest 标注 `accounting_version=cash-events-v1`、`boundary_policy=extension_window_end`。

### 追溯与监控

- 新增 `deployment_runs`，记录代码版本、Git revision、有效策略及运行配置；使用白名单，排除 API key、secret 和环境变量全集。
- 新增 `intents.run_id`。保存决策计划时冻结来源运行 ID，重启后继续沿用；旧交易保持 NULL，页面显示“历史版本未记录”。
- 新增 `execution_timing`，保留计划、处理开始、提交、响应和交易所成交时间。原订单重试不会覆盖首次提交时间；恢复查单可以补充成交时间。
- 历史页使用“净收益（不含资金费）”；账户累计收益同时展示同一区间的资金费分项，不将 Hedge 模式下仅按 symbol 提供的资金费强行归属某一方向。
- 重复的 `PLANNED_EXIT / PLANNED_EXIT` 合并显示。历史交易显示有记录的版本和容量；新增最近订单时间列表。
- `deploy.sh` 为镜像传递 Git revision；未提交工作区标记 `-dirty`，无法获取提交时标记 `unknown`，不伪造提交标识。可复现部署应使用已提交版本。

## 迁移、部署与回滚

数据库迁移只新增表及 `intents.run_id`，保留既有持仓的数量、单位、成本、执行版本、止损与 P90 参数。不会为旧持仓补造新版本，也不会改写五仓历史。新增新仓追溯与延迟信息从升级后开始积累。

在 VPS 项目目录完成以下受控升级，先构建镜像，再短暂停止交易进程完成备份和接管。已有止损单由交易所托管；暂停期间程序无法进行时间退出或抬高保护价，应避开决策和到期退出时点。

```sh
export SOURCE_REVISION="$(git rev-parse HEAD)"
docker compose build
docker compose stop trader dashboard
mkdir -p runtime/backups
backup="runtime/backups/pre-1.7.0-$(date -u +%Y%m%dT%H%M%SZ).sqlite3"
docker compose run --rm --no-deps -e BACKUP_PATH="/app/$backup" trader python -c 'import os,sqlite3; s=sqlite3.connect("file:/app/runtime/testnet.sqlite3?mode=ro",uri=True); d=sqlite3.connect(os.environ["BACKUP_PATH"]); s.backup(d); d.close(); s.close()'
docker compose up -d --wait
docker compose logs --tail=100 trader
```

部署前应已将本次代码同步到 VPS。上例使用默认数据库路径；若设置了其他 DATABASE_PATH，应使用实际路径。上线检查：心跳版本 1.7.0、无新对账阻断、原持仓与交易所数量一致、原保护单正常。后续订单应有 run_id 与执行时间记录。

真实测试网最小金额生命周期验收必须在暂停持续交易进程、确认专用账户空仓且无挂单后单独执行；本次本地测试未对仍在部署的账户下单。
