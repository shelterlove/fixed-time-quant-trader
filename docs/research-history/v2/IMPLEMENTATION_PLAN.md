## 2. 可复用与必须重写的边界

|部分|处理方式|
|---|---|
|现有本地原始行情、已修复小时行情|复用数据，记录来源和优先级；本轮不更新到最新|
|通用文件读写、基础数据结构校验、下载传输|经检查无策略语义后可复用；通过薄适配层调用|
|通用 UTC / 时区工具|可复用纯时间转换；纽约退出锚点与交易日逻辑重新写|
|因子、选币池、排名、市场过滤、信号|全部独立编写|
|持仓准入、分批资金、A50 预算、成本预留|全部独立编写|
|止损、首次激活、延期、事件优先顺序|全部独立编写|
|账户账本、权益、敞口、回撤与收益报表|全部独立编写|
|旧候选、成交、净值、汇总结果|只作对照证据，不能作为正式 v2 信号输入|
|旧策略配置和旧 protection 函数|不继承、不调用；只显式列出本版本必要常量|

禁止复制旧函数改名、包一层后称独立实现，或依赖旧交易的净收益/未来退出标签计算账户。也不需要为了“完全独立”重新写文件格式、HTTP 或时区数据库。

## 3. 目录和模块建议

```text
v2/
  README.md
  STRATEGY_SPEC.md
  IMPLEMENTATION_PLAN.md
  __init__.py
  __main__.py          # 离线命令入口；不改原入口
  models.py           # 少量明确类型：Bar、Signal、Position、Fill、Account
  data.py             # 数据清单、标准化、基础设施适配、缺口检查
  features.py         # 独立因子、两个币池、排名和市场分位数
  signals.py          # Main/A/C、新空头、原06
  allocation.py       # 准入、日预算、分批申请与可成交金额
  exits.py            # 硬止损、首次激活、一次性延长
  engine.py           # 因果事件循环与唯一账户账本
  metrics.py          # 由同一轨迹生成指标和对照摘要
  tests/              # 少量手工可验证场景
  outputs/<run_id>/   # 新产物，绝不覆盖旧研究
```

这是职责划分，不要求为了文件数量凑模块。必要时合并很小的模块，但不混合信号和账户状态、不建立泛化策略插件框架、不再生成几十个策略版本。

计算函数尽量纯函数；账户与 lot 状态集中管理；参数显式，少用跨层字典和隐式默认值。首次延长资格使用独立命名，不借用“保护已激活”字段。

## 4. 分阶段推进

### 阶段 0：说明与范围定稿 —— 已完成

产物：上述三份文档。

验收：主版本与对照明确；资金、份额、名义本金、市值不混用；收益近似和风险口径明确；未把策略选择扩展成新一轮优化。

### 阶段 1：固定数据与核验锚点

工作：

1. 固定比较窗口：2021-01-01 至 2026-09-13 13:01 UTC，采用相同最后完整小时。先不更新行情，避免版本差异混入新增数据差异。
2. 一次列出已有小时归档、补充与修复文件，明确去重优先级；只读本实验所需列和时间范围，窗口之前保留约 80 小时热身数据。
3. 现有 `hourly_inputs.pkl` 只覆盖旧候选成交路径，可用于局部核验，不能当作全市场信号重建的数据全集。
4. 对选币窗口、已有持仓路径及潜在候选路径记录数据覆盖。区分正常缺少上市前历史、历史数据中断、已退市终止和总实验边界，不能统称“无信号”。
5. 读一次旧主版本/仅止损的候选、成交和汇总，整理为只读对照锚点；不重跑旧实验。
6. 核验旧空头 `path_complete` 筛选及 R48 P50 补充表口径，登记未能证明的环节。

产物：`input_manifest.json`、`coverage.json`、短篇差异风险清单。清单记录文件路径、时间范围、必要文件元信息和行数，不做全盘内容哈希。

通过条件：数据范围与来源可追溯，缺口处理明确，已知缺陷不会静默改变候选。如果缺少必要输入，只补准确缺口或报告阻塞，不下载全量历史。

### 阶段 2：独立因子与信号

工作：

1. 从原始行情独立构建 R/P 两个池、所需因子及横截面名次。
2. 实现 L2 和 S1 信号，不读旧候选表决定当时是否有信号。
3. 将“候选”与“账户实际准入/成交”分开保存，不因没钱、有同币仓或未来价格缺失抹去信号。
4. 按 `(decision_time, symbol, source)` 对照旧候选，优先定位最早不一致点，输出该时点的币池、因子、名次和过滤原因。
5. 对旧未来路径筛选导致的候选差异单列解释，不强行使计数相等。

产物：独立 `signals.parquet`、必要的按事件特征解释、`signal_diff` 摘要；不导出所有币所有小时的无关因子。

通过条件：信号无未来依赖；差异已解释或明确定位为数据/旧规则问题。没有必要预先跑完账户去猜信号为什么不同。

### 阶段 3：退出、资金和账户独立实现

工作：

1. 写 Position/Account 明确状态，不使用旧预计算收益标签。
2. 实现入场与出场成本、盯市、日初预算、候选准入及每批等额分配。
3. 按小时检查硬止损，更新首次 +30% 时刻，在原定到期点判断是否延长。
4. 正确保留延长占用、17 点独立追加 lot、同币多空并存及日内禁入。
5. 主版本与对照只通过一个显式 `extension_enabled` 开关区分，其他规则共用新实现。
6. 输出成交/拒单/延期原因及入场时的 E0、当前权益、方向剩余额度、global_free，保证任何交易金额都能解释。

产物：核心实现、下面列出的精简算例、可重放的事件轨迹。

通过条件：手算场景正确；无持仓覆盖、无重复费用、无未结算残仓；全平后账本与成交损益勾稽。新开仓满足成本后的预算限制；旧持仓被动超预算不能误判为必须强平。

### 阶段 4：小窗口差异定位

先用少量代表场景验证：普通日、跨日持仓、17 点追加、延长跨日、止损及总终点。窗口必须有足够前置状态，不以窗口起点强行空仓冒充连续账户。

对照顺序固定为：

```text
原始行情与币池 → 因子/信号 → 准入 → 日预算 → 成交金额 → 退出 → 权益/指标
```

发现差异时停在第一处原因，不盲目重复全样本。若差异来自旧错误，记录“旧行为 / 新行为 / 依据 / 局部影响”，不以旧结果为验收真值。

通过条件：关键差异可解释，才进入完整回放。局部验证不是新的参数试验，不扫描多个止损比例或延长窗口。

### 阶段 5：一次完整双版本回放

工作：

1. 行情与独立信号准备一次，主版本和仅止损对照共用输入；需要分块时共享已准备数据，不每个变体重复扫描原始分区。
2. 各运行一次连续账户，从同一初始资金到同一总终点。
3. 由同一净值轨迹生成全区间、逐年、2026 年 9 月和风险摘要，不为每个年份重新跑策略。
4. 对账，再与已保存的两组旧结果比较。
5. 若必须修复错误，只重算受影响环节；先局部验证修复，再执行确有必要的完整回放。

产物建议：

- `run.json`：明确策略常量、窗口、行情近似、成本和未计项目。
- `signals.parquet`、`decisions.parquet`、`trades.parquet`、`equity_hourly.parquet`。
- `summary.json`、`periods.parquet`、`comparison.md`。

不复制大行情文件到每个输出目录。输出列按审计需要裁剪，不制造几套含义相同的中间表。

通过条件：所有重要差异都有归因；金额误差按相对尺度评价，例如局部账本 `1e-10` 量级相对容差，而不是要求巨额复利终值小数位完全相同。候选集合、方向、退出原因等离散差异不能当浮点误差忽略。

### 阶段 6：审查与交付

交付报告必须回答：

1. 策略重写是否独立，是否违规调用旧信号/资金/退出模块？
2. 旧候选筛选、资金、退出或指标是否存在错误？分别影响什么？
3. 新旧收益和两类回撤差异来自哪里？仅止损与延长差异来自哪些交易和后续占用？
4. 跨年收益是否都为正、是否集中在少数年份；逐年回撤和最差月份/日期如何？
5. 多头是否贡献实际价值，多空是否在亏损时段提供抵消，而非只看总收益？使用已有双版本轨迹分解，不另跑策略网格。
6. 约 50% 风险要求：收盘与盘中近似分别如何；不能验证的地方是什么？
7. 巨额复利是否依赖少数大赢家、市场容量或未计成本，哪些结论只能停留在理论回测？

随后给出“实现可接受 / 仍有明确问题”的结论。没有新授权不自动接实盘、改原入口、推送代码或启动新优化。

## 5. 必要而有限的验证清单

每类用最小可手算数据，不为覆盖率数字制造无意义测试；多个边界可合并为参数化算例。

|类别|必须证明的行为|
|---|---|
|信息时序|改变决策点之后的行情，不改变该时点因子/信号/申请预算；不得从未来退出标签取资金信息|
|币池与名次|R/P 资格差异、并列排序、绝对 TOPN、历史 02 点池、分位数半整数舍入|
|资金份额|100 初始权益的 00/01、14/15、15/17 三种分批，以及有旧仓时剩余额度|
|参考权益|00 点先结算再冻结 E0；00 点无信号也更新；日内盈利不提高预算、亏损会收紧|
|账户成本|多空各一笔完整手算，入场费一次、退出费一次、平仓损益勾稽|
|同币与同日|17 点追加独立 lot；普通重复买入拒绝；止损日锁；空头退出后允许后来时段重入|
|止损优先|同小时达到 +30% 与止损，必须止损，不激活、不延长|
|跳空|多头低开穿阈值/空头高开穿阈值按更差开盘价，再加入交易成本|
|延长边界|首次激活恰在 P-4h 不延长、P 可以延长；早激活后创新高不重置；只延一次到 P+24h|
|占用与互不清退|延长始终占用本金；资金不足不得平未到期空头；亏损超预算只限制新开仓|
|纽约时间|夏令时和冬令时各一个明确日期，以及切换附近的退出点|
|统计与边界|跨月/年状态不断裂、总终点清算一次、最差日包含浮盈亏、空头看 high、退出后极值不再计入|
|缺口与候选|历史窗口缺口使因子无效；未来路径不完整不能删除当时信号；实际持仓缺口必须显式失败|

交易数不是硬性对齐目标：信号修复、17 点 lot 分拆或延长占用都可能改变交易数，必须给原因而非只说多了/少了。

## 6. 节制执行约束

- 不重复下载现有数据；本次先固定旧比较终点，不同步最新行情。
- 不做全目录哈希、无关仓库体检、格式化整个 v1 或无关测试。
- 不重新扫描历史策略、重新比较几十组组合、扩大参数搜索。
- 不同时改资金方案、盈利保护或杠杆；发现需要变更策略而非修 bug 时，先提出选择。
- 耗时任务按阶段输出有意义的进展，不频繁轮询；计算是否重跑要有明确原因。
- 数据缓存是性能工具，不能使策略依赖旧因子/信号结果；允许新独立特征按明确版本和输入清单复用。
- 保护当前工作区已有改动，不清理旧研究与结果。

## 7. 模型与思考等级建议

**推荐主选：GPT-6 Astra + Extra High（xhigh）。**

理由是本任务的难点在跨模块一致性：时间因果、候选资格、名义本金和权益、入场费与退出结算、同小时事件顺序，以及解释巨大复利差异。不是代码行数多，而是多个看似合理的局部实现容易组合出错误。

- 想简单执行：整个核心实现和最终审查均使用 Astra + xhigh。
- 想兼顾速度：普通 I/O、报表和明确的小修改使用 High；策略规则、资金账本、差异定位和最终审查使用 xhigh。
- 不建议默认使用 Max/Ultra；更高档位不能替代清晰说明、手工算例和数据对账，也不需要为此自动启动并行代理。
- 若客户端没有该模型或等级，以实际可选项为准，不保证账户可用性；无需修改账号或 API 配置。

这是针对本项目的判断，不是正确性的保证。按 OpenAI Docs 技能核对的官方资料：

- [GPT-6 Astra 模型说明](https://developers.openai.com/api/docs/models/gpt-6-astra)：模型定位与支持的推理等级。
- [官方模型与思考等级说明](https://learn.chatgpt.com/docs/models)：模型选择、High / Extra High 及更高档位的适用场景。

文档核对日期：2026-09-17。模型建议只用于后续工作的选择，本计划不执行模型切换。
